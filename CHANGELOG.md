# Changelog

All notable changes to `dsh-expert-orchestrator`. Format loosely follows Keep a Changelog; versions are plugin semver (independent of the host `dsh` version, which is declared via `engines.dsh` / `peerDependencies`).

## [2.8.0] — 2026-10-09

### Added

- **WP-7 — delegation safety gates (M8-2; T26/T27/T28)**
  - **Origin chain recursion protection (#21, T26, `730e945`)** (`lib/origin-chain.js`): every summon appends a single-line marker `<!-- origin-chain: [{"n":"<expert>","c":"<cwd>"},…] -->` to the end of the task brief, one (expert, cwd) hop per entry; the dispatch entry parses the chain carried in the brief, **rejects on any repeated (expert, cwd) pair** and reports the full chain (e.g. A→B→A), and derives depth from the chain length (no trusted counter field). The toolFilter deny list is intersected with the host's `restrictableNames` (schema enumeration first, per-name probe fallback; unregistered names are dropped with a warning). Default **on** — merged behind a pre-registered A/B experiment archive (`docs/internal/experiments/2026-10-09-origin-chain-ab/`, committed by T35 `ef0a9fc`: 18 probes across 3 books × A/B × n3 — P1 reach 9/9, P2 propagation fidelity 9/9, P3 no false disturbance 9/9, gate passed; judgment re-derivable from `raw-probes.md` verbatim, timing wording finalized by T37). `DSH_EXPERT_ORIGIN_CHAIN='0'/''` switches it off (byte-identical fallback to the pre-existing brief).
  - **Four small gates (#22, T26, `730e945`)**: **artifact ownership** — `taskboard.py own <task> <path>...` registers ownership; conflicts with other open tasks return the named error `artifact_owned` (terminal tasks auto-yield; re-registering for the same task is idempotent; `TASKBOARD_DISABLE_OWNERSHIP=1` escape hatch); **delegation oscillation warning** (`lib/oscillation.js`, non-blocking) — alternating A→B→A dispatches between the same expert pair trip a warning line at the summon tail (default 3 round-trips, `DSH_EXPERT_OSCILLATION_N` tunable, `DSH_EXPERT_OSCILLATION='0'/''` off); **effort preflight** (`lib/effort-preflight.js`) — a profile `effort` value degrades with a one-line warning when the provider does not declare the `agentOptions` capability, never blocks; **per-cwd write lock** (`lib/cwd-lock.js`, opt-in `DSH_EXPERT_CWD_LOCK=1`) — a second differently-named write expert on the same cwd (realpath-normalized) is rejected at the summon boundary with the holder named and three ways out (wait / cancel / declare `readOnly: true`); same-pid same-name dispatch counts as re-entrancy, a dead holder is stolen via ESRCH. T37 repair (`cba9271`): re-entrant release decrements by the file's original token and unlinks only at zero; O_EXCL creation writes through the fd and re-verifies the inode via `fstat` before locking, closing the double-hold window; `tools.js` enters the try/finally-protected section immediately after acquire.
  - **Per-expert tool-call hard budget (#16, T27, `e4f16ae`)** (`lib/budget.js` + `taskboard.py` budget enforcement): execution-plane write commands (claim/progress/heartbeat/done/fail/own/vote) count per-(task, expert) with the **event stream as the only counting source — model self-reports never count** (bus messages, checkpoint texts and any narrative content are not inputs; orchestration-plane commands and seed/budget system events are excluded, so the "record tier → count grows → record again" self-excitation loop is closed); counts accumulate across attempts and reclaims. **Three fixed tiers, tunable thresholds** (`DSH_EXPERT_TOOL_BUDGET_ALARM/_WRAPUP/_INTERRUPT`, default 200/250/300, must satisfy alarm ≤ wrap-up ≤ interrupt — invalid configuration fails open with a stderr warning): **alarm** — non-blocking spend hint + `budget.tier` stamp visible on the event stream; **wrap-up** — non-blocking convergence instruction auto-appended to re-summons of that task (lib consumes the `budget --json` envelope); **interrupt** — advancing calls (claim/progress/heartbeat/own) are refused on the spot with the named error `budget_interrupted` (the first refusal lands a `type=budget` system event, later refusals are idempotent zero-event; **delivery exits done/fail are never refused**). `budget <id>` is a read-only inventory (`data.budget` payload: enabled/thresholds/epoch/stamped/budgets) and `budget <id> --reset` is the orchestrator's explicit epoch reset (event + checkpoint evidence). Opt-in `DSH_EXPERT_TOOL_BUDGET` — default off with a byte-identical write path when off.
  - **Idle-edge auto re-claim (#20, T28, `533ae96`)** (`lib/idle-reclaim.js`): when the session's **last in-flight expert run ends successfully** (the summon idle edge; failure edges never scan — prefer missing over wrong), the lib side sweeps the cwd's unique taskboard once and claims `ready`/unowned entries (≤8 per sweep) as **owner=编排者 through the existing claim path** (`show` re-check → `claim --expected-revision` CAS → event-sourced; no attempt generation is created). **Claim ≠ dispatch** — the sweep never summons or spawns an expert; dispatch stays with the orchestrator (sync the owner to the actual executor via `reassign` when dispatching). Both trigger conditions must hold: session idle (no other in-flight run) and no `running` tasks on the board. Budget/watchdog interlock: re-claims ride the claim path so the per-(task, expert) counter carries over — an interrupt-tier counter refuses the re-claim until `budget --reset`; reclaimed-by-watchdog tasks re-enter the sweep under the same budget. Opt-in `DSH_EXPERT_IDLE_RECLAIM=1` (default off per user ruling; unset/`0`/empty = off with zero board reads).
- **WP-6 remaining items (#17/#19, T15, `3d214ff` + repair `3d7cca3`)**
  - **Per-expert heterogeneous profiles (#19)** (`lib/expert-profiles.js`): expert profiles resolve from `<cwd>/.dsh/expert-profiles.json` (project layer) over `~/.dsh/expert-profiles.json` (global layer), format `{"experts": {"<name>": {"model", "tools": {"allow","deny"}, "skills", "mcp", "effort"}}}`, all fields optional; re-read at every summon — **hot file edits take effect on the next summon and revert on restore, no host restart**. Effective faces: `model` → subagent model override (provider must declare the `agentOptions` capability; older hosts degrade visibly); `tools.allow/deny` → subagent toolFilter (union with the recursion-protection deny — **never widens**; unregistered allow names are filtered by probe; an empty allow is passed as empty — fail closed); `mcp` → MCP server allowlist expanded into `mcp__*` denies for non-allowlisted servers (needs the host tool-enumeration face, degrades visibly when missing); `skills` → prompt-level allowlist constraint lines appended to the **tail of the final persona** (T34 repair: injection moved after the `<!-- methods-cut -->` layering cut — previously the constraint lines of top-5 layered experts were silently dropped). `DSH_EXPERT_PROFILES=0`/empty disables. No profile configured = byte-identical behavior.
  - **Prompt slimming (#17)**: persona guidance sections wrapped in `<!-- tools: a,b -->…<!-- /tools -->` are pruned when **every** named tool is invisible to that expert (profile narrowing ∪ recursion-protection deny ∪ registration probe); sections with any visible tool survive; unpaired markers or empty lists fail safe (no pruning). Implemented in one place at persona assembly (`lib/tools.js`). An accompanying repair (same commit): the auto-claim failure hint prefers the envelope `message` (`message ?? error ?? stderr`).
- **Review-backlog ledger closure (T17/T31, `6d68289`)** — all 14 backlog items from the v2.7 review rounds dispositioned (10 implemented, 4 written rulings): **S1** `taskboard.py --json` structured envelope (lib auto-claim consumes the envelope; failure hints prefer `message ?? error ?? stderr`, +11 cases); **S3** bus mailbox-root convention documented with `stats` reconciliation; **S4** archive same-second collision gets a unique suffix; **A3** a view ahead of the event stream upgraded to `unrecoverable`; **B4** orphan-guard on a corrupted archived board degrades with an explicit notice (fail-closed); plus a WP-2(f) mixed-safeguard case, a spray-surface comment fix, the §9 transition hint, and the `from` delimiter annotation (comment + case). Written rulings (documented, not implemented): event-stream compaction (needs a seq index before ~10k events), multi-machine clock premise (single-host single-clock), truncation-marker budget edge (constant-size overage, no real harm), subject-side negative guard (narrow false-adoption face vs wider false-kill face).

## [2.7.1] — 2026-10-09

### Fixed

- Documentation-only patch release (no code changes in 2.7.1 itself): the three v2.6 defect fixes below shipped with the 2.7.0 code but were folded into its Added/Changed narrative — this entry adds their explicit release record, as recommended by the v2.6 defects retrospective (2026-10-09).
- **bus.py — cross-generation filtering misjudged legitimate reports** (v2.6 D1): a `bus.py read` without `--board` resolved the default board to a stale unrelated board whose task `attempt_id` disagreed with the report's `--attempt`, so valid completion/checkpoint reports were silently archived as "not the current attempt generation" (during the 2.7 cycle this removed two T10 reports from the coordinator inbox). Fixed by the multi-board tri-state verdict in T11 (`5c2538e`): the primary resolution board is strict (missing/corrupt → unrecoverable), same-workspace candidate boards may only confirm and never veto, an explicit `--board` is strictly single-board, and revocation records take precedence; the incident messages were replayed and recovered, with 6 regression scenarios.
- **taskboard.py — missing board file masked as "task not found"** (v2.6 D2): a `--board` pointing at a nonexistent file was treated as an empty board, so commands reported 「任务不存在」 and left a 0-byte `.lock` remnant behind instead of a board-missing error — sending triage down the wrong path. Fixed by the strict semantics in T11 (`5c2538e`): a missing/corrupt primary resolution board is an unrecoverable error, and an explicit `--board` is validated strictly.
- **`scripts/gen-preset-declaration.mjs` — dead on arrival in the shipped 2.6.0** (v2.6 D3): after `agent.cordis.yml` became a pointer document the `-id` lines the script parsed no longer existed, so declaration regeneration crashed — a pre-existing broken script with zero test coverage. Revived by T14 (`73a54c1`) with `--roster`/`--empty-roster`/`--check`, an idempotency invariant (empty-roster output byte-identical to HEAD, 13483 B) and negative-sample failure cases for malformed artifacts.

## [2.7.0] — 2026-10-09

### Added

- **WP-4b — crash-safe orchestration state (event sourcing)**
  - **Event-sourced taskboard** (T10, `taskboard.py`): the append-only event stream is the authority for board state — reads render a folded view over events, board files carry a dual-layer integrity hash, and a corrupted/truncated board replays deterministically from the event log instead of surfacing a silently empty task list.
  - **Bus cross-generation tri-state verdict + incremental reads + watchdog/adopt** (T11, `bus.py`/`taskboard.py`): bus reads filter by dispatch generation with an explicit three-state verdict (deliver / skip-round hint / archive), senders get monotone `seq` numbers so consumers can read incrementally (`--since-seq`), and a sliding-window watchdog detects silent `running` tasks — orphans with persisted completion evidence on the bus are adopted (attempt preserved) instead of being blindly reassigned.
  - **Summon resume (continuation)** (T12, `lib/tools.js`; new-generation hosts only — user ruling 2026-10-07 Q2=2A): on hosts exposing the continuation lifecycle the summon channel rebuilds an interrupted expert run as a durable continuable subagent and delivers exactly one resume turn whose prompt folds in breakpoint data (latest taskboard checkpoint + bus reports + partial pre-interrupt output); old-generation hosts keep the one-shot behavior unchanged, and `DSH_EXPERT_RESUME=0` force-disables the path. Protocol §3/§9 rewritten around it.
- **WP-5 — quality gates on the taskboard**
  - **Staged plan drafts** (T18): `taskboard.py create --draft` parks PM plans in a `draft` state — not claimable, not auto-promoted by dependency resolution — until an explicit `approve` flips them to `ready` (WP-5/S1 zero-spawn enforcement before approval). Protocol §2 gains the plan/draft/approve three-stage.
  - **Review kind** (T19): `create --kind review` marks acceptance subtasks; completion requires an explicit `--verdict` with `findings` hard-validation, a failed review auto-routes the task through repair and re-hangs downstream dependents, and an unresolvable review lands in the new `escalated` terminal state for user disposition.
  - **m-vote boolean consensus** (T20; user ruling Q3=3A — default m=3, review-round limit 2): `create --kind review --quorum-m [N]` convenes an N-reviewer jury; reviewers cast `taskboard.py vote <id> --by <name> --score <0..1>` (exactly 1 = pass, exactly 0 = fail, in-between = abstain; one vote per reviewer per round, re-votes rejected with a named error). A verdict takes effect only with ≥m same-direction votes **and zero reverse votes**; any reverse vote deadlocks → `escalated`. Every return-to-`ready` path (user retry, failed retry, watchdog reclaim, recover) resets the ballot so stale votes can never fake a quorum.
- **WP-6 — file-layer experts & zero-token gestures**
  - **Expert definition files** (T13, `lib/expert-files.js`; user ruling Q4=4A): experts resolve through a three-layer exact-name chain — project `<cwd>/.dsh/experts/<name>.md` > global `~/.dsh/experts/<name>.md` > bundled core (read-only fallback) — and file edits take effect immediately at summon time (runtime re-read, no restart).
  - **Zero-token expert gestures** (T14/T21): the 11 bundled core experts are additionally registered as `modelInvocable:false` host skills under `skills/expert-gestures/expert-<name>.md` (generated together with the preset declaration by `scripts/gen-preset-declaration.mjs`); typing `/expert-<name>` deterministically injects the persona via the host pre-step hook with zero model invocations and zero catalog token overhead. `scripts/verify-gesture-declaration.mjs` re-verifies the parsed declaration mount on any generation's host modules.
- **Protocol refresh drill (WP-8 ②, this release)**: simulated a VERSION bump (`2.6.0+sources1` → `2.7.0+sources1`) against a sandboxed `config.targetDir` through the real `apply()` path. All 14 PROTOCOL entries — including the new `skills/expert-gestures` directory (11 gesture files) — were overwritten byte-identical from the package; USER_DATA (`lessons.md`, `expert-lessons/`, `expert-methods/`) was only ever copy-if-missing (pre-seeded user content untouched, missing bundled files created); an extra non-core file inside the bundled `experts/` dir was migrated (not deleted) to `expert-sources/legacy-adapted/` per the documented upgrade semantics; the user `~/.dsh/experts` file layer outside the deploy tree was untouched. Extends the v2.6.0 drill (13 items, no gesture dir) with the v2.7 command/dir surface; real deploy directories were not modified during the drill.

## [2.6.0] — 2026-10-08

### Added

- **WP-1 — taskboard concurrency correctness** (`taskboard.py`): CAS `expected_revision` optimistic locking on every write (stale revision returns a named error and never touches the file); attempt generations (reassignment revokes the old attempt, done/report from a stale attempt id are rejected); explicit `unrecoverable` error objects on corrupted board files (never a silently empty task list); full dependency-graph cycle detection before dependency writes.
- **WP-2 — message-bus delivery semantics** (`bus.py`): at-least-once delivery (the cursor advances only after a success receipt); reads filter by the current attempt generation and archive expired messages instead of exposing them in the inbox; explicit skip-round hint when the inbox contains only expired messages; atomic writes throughout.
- **WP-3 — enforcement plane** (opt-in): a zero-dependency `commit-msg` hook template with triple check (message format + task existence + file scope), installed into the user repo's `.git/hooks/` only on explicit request; verification receipts are bound to per-file SHA-256 scope fingerprints — any file change after a receipt marks it stale/invalid.
- **WP-4a — auto-claim on dispatch** (`summon_expert`): task ids parsed from summon briefs are claimed automatically (in_progress + owner) before the expert runs; fail-open with a visible hint, never blocks dispatch.
- **WP-8a — host settings migration**: the plugin's user-facing configuration is registered on the host schemastery namespace (插件配置 page); every settings write carries `expectedRevision` optimistic concurrency and returns a named error on conflict. All settings registration is fail-open — bare checkouts and degraded builds still load the plugin.
- **Protocol refresh drill (WP-8 ②, this release)**: simulated a VERSION bump against a sandboxed `config.targetDir` and verified that all PROTOCOL entries (13 items, including `SKILL.md`, `taskboard.py`, `bus.py` — all touched by this iteration) are overwritten wholesale by `refreshEntry`, while user data (`lessons.md`, `expert-lessons/`, `expert-methods/`) is only ever `copyIfMissing` and is not touched. Real deploy directories were not modified during the drill.

### Changed

- **peer/engines — 0.2.1-alpha host line**: `engines.dsh` and the `@deepseek-ai/dsh-tools` peer range gain the branch `>=0.2.1-0 <0.3.0-0`. Under strict semver, a prerelease version only satisfies a range when a comparator carries a prerelease on the same `[major, minor, patch]` tuple — `0.2.1-alpha.1` does **not** match `>=0.2.0-rc.1 <0.3.0-0` (tuple `(0,2,1)` ≠ `(0,2,0)`). Note for future 0.2.x patch prerelease lines (e.g. `0.2.2-alpha.x`): each line needs its own branch appended.
