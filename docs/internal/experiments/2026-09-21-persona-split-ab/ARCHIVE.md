# 实验档案：persona 方法论分层 A/B（瘦 persona + method 指针 vs 全量注入）

> 实验纪律（SKILL.md §8）：引导段 / 协议文本 / persona 类改动合入前必须跑对照实验——同任务书、n≥3、判定标准先写后跑。一实验一档；判定标准在首跑前预注册，跑后不得改判；结论只陈述已验证事实。

- **日期**：2026-09-21（预注册先于实验落盘；执行后补记结论）
- **执行人**：编排者（coordinator，探针发射与判定）；档案整理：后端工程师（backend-engineer）
- **对象改动**：P2 persona 方法论分层（T3 splitPersona 工具支持 + T4 Top-5 persona cut 标记与 expert-methods 内容）——本实验为「瘦 persona 合入默认行为」的门禁
- **对照组 / 实验组**：A=全量 persona 注入（现状行为）；B=瘦 persona（`<!-- methods-cut -->` 之前部分）+ 尾行「领域方法论全文在 <abs 路径>，任务复杂或触及清单场景时先 read 再动手」

## 假设

- **H1（遵从不降）**：瘦 persona 子代理对任务书关键操作规则的遵从率不低于全量 persona。
- **H2（锚点存在）**：method 指针行随 persona 注入到达子代理（引用探针可见），构成「复杂任务先 read 再动手」的可用锚点。

## 设置

- 探针执行者：编排者（仅编排者持有 summon/subagent 通道），spawn 全新子代理；prompt = persona 文本（A 或 B）+ 代表任务书 + 末尾指令「逐字引用你收到的角色指令的首行与末行」。
- 代表任务书 ×3（每条预注册 3 个判定点）：①backend-engineer·小修复（核实先行/范围约束/可运行验证）②tech-writer·文档回写（先读再改/文档与行为一致/按格式落盘）③code-reviewer·评审（只读不改/结构化结论/分级输出）。
- 执行时点：T4 材料 + splitPersona 接线（T3）就绪后；探针统一约束受控模拟（禁止真实写文件，交付写回复，判定点按声明行为计分）。

## n

每条件 × 每任务书 n=3，共 3×3×2=18 次探针（A1–A3 / B1–B3 × 3 角色）。小 n 冒烟门禁，不做显著性检验。

## 判定标准（预注册）

- 到达率：首尾行引用正确比例 ≥ 2/3（B 条件末行必须含 method 指针行）。
- 遵从率：B 条件每任务书判定点通过率 ≥ A 条件同任务书通过率（不劣于）。
- 完成质量：交付结构按任务书逐项核对（结构完整即可，不评文风）。
- 门禁：全部满足 → 瘦 persona 可为 Top-5 默认；任一不满足 → 保留全量注入、T4 内容保留但默认关闭（配置回退），结论照实入档。

## 原始产出路径

- 预注册与结论补记：`.expert-reports/t5-persona-split-experiment-preregistration.md`
- 18 探针原始全文：`.expert-reports/t5-persona-split-raw-workflow.txt`（workflow「t5-persona-split-ab-experiment」返回值）

## 结论

1. **到达率（H2 ✔）**：首行 18/18、末行 18/18 逐字正确；B 条件末行=method 指针行 9/9（例：B2-backend 逐字引用「领域方法论全文在 /vol2/.../expert-methods/backend-engineer.md，任务复杂或触及清单场景时先 read 再动手」）——≥2/3 达标。
2. **遵从率（H1 ✔）**：3 任务书 × 3 判定点，A 组 9 探针全过（27/27），B 组 9 探针全过（27/27）——B 不劣于 A。备注：任务书 1 的端点前提被两组一致证伪（dsh-onebot 无 REST 端点），两组均以「只读核实先行、拒绝编造、声明未验证、上报他人在途改动」满分级通过。
3. **深读可用性**：B 组复杂场景探针（backend B3、code-reviewer 全组）主动 read methods 并套用检查表（如 API 契约检查表逐项核对），无跑题读取、无有害行为。
4. **门禁判定：通过**——瘦 persona（method 分层）可为 Top-5 默认合入。
5. **局限（如实）**：受控模拟（交付写回复不落盘，非真实落盘质量）；任务书 1 前提失真使其实际度量的是拒止合规而非实施质量；n=3 冒烟口径；bundled-core 5 份 persona 本就紧凑（18–20 行，cut 标记在正文末），本实验等效验证「指针行+按需深读无害且可用」——遵从收益的上限在长 persona / custom 专家场景，本次未覆盖。

## 决策

- **瘦 persona（method 分层）合入为 Top-5 默认行为**（门禁预注册标准全项满足）；来源包专家无 method 键=行为零变化（T3 回归锁用例 + 本实验 A/B 设计共同保障）。
- 后续若扩展到长 persona / custom 专家，需按本模板另立实验档案（新假设：分层在长 persona 上的遵从增益），不得引用本档案结论外推。
