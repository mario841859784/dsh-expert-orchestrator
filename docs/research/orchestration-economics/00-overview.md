## 1. 问题定义：编排者的经济学决策面

一个「编排者 + 子代理专家」插件在每个任务上隐式做三类经济决策：

1. **规模决策**：用几个专家、什么深度的流程（专家数量的边际收益递减，且有负收益区间）。
2. **路由决策**：每个子任务用什么模型、什么 persona（模型能力与价格的强非线性）。
3. **上下文决策**：给每个子代理多少上下文、如何组织前缀、回传多少（token 与缓存命中决定实际单价）。

三条研究线分别对应这三类决策，且交叉印证出一个统一结论：**成本是编排决策的一等公民，而缓存命中率是其中杠杆最高的单一变量。**

## 2. 三条研究线的核心发现

### 2.1 路由与调度（详见 01）

- **DAAO**（arXiv:2509.11079，WWW 2026）是目前最接近「调度大脑」的完整方案：VAE 无标签难度估计 + 分层算子分配 + 成本-性能路由（λ 偏好旋钮）+ 成功/失败自调整。六基准 +3.5~15.2%，MATH 成本仅为 AFlow 的 10.4%。
- 但其局限被后续工作点名（arXiv:2609.22951）：**整轨迹单一难度标量太粗**，成本削减仅 36.2%。难度应做到**子任务级**。
- 路由方法谱系：RouteLLM（>2× 成本削减）→ FrugalGPT 级联（最高 98%）→ GraphRouter（≥+12.3% 但训练型路由器 CPU 慢 5460×）→ Router-R1 / MasRouter。工业界 OpenRouter/Not Diamond/Bedrock/GPT-5 内建路由均已产品化。
- **专家数量不是越多越好**：DeepMind 大规模实验（arXiv:2512.08296）显示多代理架构增益横跨 −70%~+80.8%，87% 配置可预测最优架构；同质专家受信息论上界约束（arXiv:2602.03794）——**扩编的价值来自异构视角 + 中心校验，不是人头**。

### 2.2 缓存成本经济学（详见 02）

- 定价事实（2026-11 核实）：Anthropic write 1.25×(5min)/2×(1h)、read 0.1×；OpenAI 自动 0.5×；DeepSeek 命中价仅为 miss 的 2–3.3% 且必须从 token 0 前缀一致；Gemini 75% 折扣 + 显式存储费。**read 折扣 ≫ write 溢价，命中几乎永远正期望。**
- 多代理的 token 放大是实测的：Anthropic 官方多代理研究系统报告多代理 ≈15×、单代理 ≈4× token，token 用量解释 80% 成功方差；effort 规则硬编码（简单=1 代理 3–10 调用，比较=2–4 子代理各 10–15，复杂≤10+）。
- **组版得当可把 15× 名义放大压回 ~2–4× 有效成本**：稳定前缀分层、1 write + N read 预热 stagger、亲和路由（llm-d）、append-only 组版。
- 反模式（直接杀死命中）：变化字段拼前段、每子代理不同 system 措辞、多轮重写历史。

### 2.3 Context engineering 主线（详见 03）

- Anthropic《Effective context engineering for AI agents》：attention budget / context rot；长时程三技术分工——compaction（对话往复）/ structured note-taking（里程碑迭代）/ sub-agent（并行探索，回传 1–2K token 摘要）。
- Cognition《Don't Build Multi-Agents》vs Anthropic 多代理博客的分歧**实为任务类型划分**：读型可并行任务多代理 +90.2%（代价 15× token）；写型强依赖任务必须全轨迹共享。**编排插件的首要分流 = 读型/写型。**
- Manus 实践：KV-cache 命中率是生产期单一最重要指标（100:1 输入输出比、10× 价差）；前缀稳定、append-only、mask don't remove、文件系统即上下文、保留失败轨迹、todo 复诵。
- 理解-生成不对称（arXiv:2507.13334 综述）：转述必失真——上下文交接应「落盘 + 引用」，不应「摘要复述」。

## 3. 交叉综合：三条线互相锁定的结论

1. **分流先于一切**：读型/写型分流是路由（01）、缓存（02）、上下文（03）三条线的共同前置判断。读型任务才允许扇出；写型任务走单代理 + 全轨迹共享。
2. **难度分级是路由的输入，effort 分级是规模的输入，任务类型是拓扑的输入**——三者共同构成派工决策函数的三个轴，缺一就会退化成「一律 3 个子代理、一律旗舰模型」的粗放编排。
3. **缓存组版是最便宜的优化**：模型路由要训练或接 API，而缓存组版只是改任务书的拼装顺序——02 的定价数字表明它是零研发成本、立即生效的最高杠杆。
4. **成本必须进入决策与反馈回路**：路由目标含成本项（01）、派工决策含缓存策略（02）、回传结构化摘要而非全文（03）——三线在此汇合为同一个闭环：**决策时算账，执行后回收计量数据校准难度估计**。
5. **编排者自身的成本不可忽略**：Free-Executor Paradox（02）与轻量路由器要求（01）一致——编排/路由层必须比执行层便宜若干个数量级，否则调度省的钱不够调度花的钱。

## 5. 与本插件现状的初步对照（非实施承诺）

- v2.13.x 已有按专家分组的模型设置（model groups/defaults），即 01 中「路由决策」的静态版雏形——升级方向是按**任务难度**动态选档而非按专家固定。
- 现有任务书组版（固定段前置 + 逐字复制）天然接近缓存友好前缀；02 的 D1 可指导进一步把「变化字段后置」做成规范。
- 现有经验池与任务板检查点与 03 的 structured note-taking / 检查点交接同构，可作为上下文经济学的既有落点。
- acp_cache 类命中率回传（02-D5）目前无插件侧采集点，属于全新能力。

## 6. 证据强度与遗留问题

- 定价数字为调研时点核实（2026-11），厂商调价频繁，落地前应重查。
- DAAO 一类学术结果均在基准环境测得，与真实插件工作负载（长任务书、异构专家）有差距；后续 arXiv:2609.22951 已指出其成本削减被高估。
- 「难度估计器」在插件场景的可行形态（LLM 自评 / 历史统计 / 轻量分类器）三条线均未给出定论，是下一步值得单独调研的开放问题。
- web_fetch 端点在调研期间故障（404），03 报告部分来源经 SearXNG 抓取，出处 URL 已核对。
