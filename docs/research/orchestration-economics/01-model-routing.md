## 0. 结论速览

1. 「按难度路由」已从单一模型二元路由（强/弱模型）演进到三层调度：**模型路由**（RouteLLM/GraphRouter）→ **工作流级路由**（MasRouter：协作模式+角色+模型）→ **难度感知编排**（DAAO：难度→工作流深度→算子→异构模型）。
2. 「智能体数量越多越好」不成立：DeepMind 的规模化实验表明**架构-任务对齐**决定成败，错配可致 −70% 相对性能；信息论分析表明同质智能体的收益受任务内在不确定性约束。
3. 对编排者插件的落地含义：难度分级要可学习、路由输入要含成本项、团队规模要按任务可分解性伸缩、必须内建回退与校验。

## 1. DAAO 精读：Difficulty-Aware Agentic Orchestration

**论文**：Su et al., *Difficulty-Aware Agentic Orchestration for Query-Specific Multi-Agent Workflows*，[arXiv:2509.11079](https://arxiv.org/abs/2509.11079)（v1 提交于 2025-09-14，v5 2026-02-13，**已被 WWW 2026 接收**，DOI 10.1145/3774904.3792240）。代码：[github.com/AutoAgents-ai/DAAO](https://github.com/AutoAgents-ai/DAAO)。

> 委派任务中的出处提示「约 2025-06 arXiv」有误：该论文实际首次提交于 **2025 年 9 月**（arXiv 编号 2509.11079），是 v5 版、WWW 2026 正式接收版。下述内容基于 v5。

### 1.1 问题定位

现有多智能体框架要么是**任务级**（一个固定工作流服务整个任务类别，如 AFlow/MCTS、ADAS/启发式搜索）——对简单查询过度处理、浪费 token；要么是**查询级**（如 MaAS 的 agentic supernet）——粒度不足以按难度伸缩，难查询会被「过简化」。此外多数框架 LLM 同质（单一 backbone），忽略异构模型的性价比差异。**[论文主张]**

### 1.2 方法：三个模块 + 自调整策略

- **难度估计器**：VAE（带难度头）把查询编码为潜表示并输出标量难度 z，从后验知识学习，**不依赖人工难度标签**；难度定义为可学习策略而非固定打分。
- **分层算子分配器**：工作流建模为分层 DAG，节点是「算子 = (模型, 协作协议)」对（协议目录含 CoT、LLM-Debate、Review、Ensemble、ReAct、Self-Consistency、Testing）；策略 π_l(O) = P(O | Q, z) 逐层选择算子子集，最大层数 L_max = 5，即**工作流深度随难度可变**。z=f_φ(Q, H_{1:l-1})，即难度信号会随已选算子的历史自适应更新。
- **成本-性能感知 LLM 路由器**：按难度与资源约束把异构模型分配到各算子（模型池：gpt-4o-mini、gemini-1.5-flash、llama-3.1-70b、qwen-2-72b）。
- **自调整策略（reward-like 反馈环）**：工作流成功 → 略微下调该查询的预测难度（未来走更简工作流）；失败 → 上调难度（更复杂工作流）。训练时 controller 采样架构并以成功信号更新策略。

优化目标是任务效用与推理成本的加权和（成本惩罚系数 λ ∈ {1e-3, 5e-3, 1e-2}），训练/测试切分 1:4，每实验跑 3 次取平均。**[论文实测，实验设置]**

### 1.3 实验结论 **[论文实测]**

- 六个基准：GSM8K、MATH（取 617 题较难子集）、HumanEval、MBPP、MMLU、GAIA。
- 相比自动编排方法（ADAS/AFlow/MaAS）平均准确率 +3.5%~15.2%；相比 LLM 路由方法（RouteLLM/MasRouter/PromptLLM）+3.2%~10.2%。
- MATH 上取得最佳 55.37%（次优 MasRouter 52.42%）。
- GAIA 上平均 25.97 vs MaAS 17.64、AFlow 8.00（三个难度级别均领先）。
- 成本：MATH 基准上训练 $2.34 + 推理 $0.27 = $2.61，仅为 AFlow（$24.16）的 10.4%/16.3%；训练成本为 MasRouter 的 65%、推理成本为 41%，同时准确率更高。
- **归纳泛化**：加入未见过的 DeepSeek-v3 后，路由器在 MATH/MMLU 上分别有 29%/15% 的查询选择新模型，MATH 准确率 55.37%→56.20%，说明无需重训即可纳入新模型。跨域联合训练（MATH+GSM8K、HumanEval+MATH）带来 0.35%~1.05% 提升且不遗忘。
- 案例研究：简单查询只生成单算子精简工作流，中难查询生成更深、更复杂的工作流——印证「深度随难度伸缩」。

### 1.4 局限与外部批评

- **作者自述**：未覆盖多模态查询；缺乏实时反馈整合（未来工作）。**[论文自述]**
- **整任务单一标量难度**：后续工作（arXiv:2609.22951，[PDF](https://export.arxiv.org/pdf/2609.22951)）批评 DAAO 的 VAE 给整条轨迹打一个难度分、按最难步骤为全部步骤供给资源，其成本削减因此只有 36.2%（对比按步供给的方法 98.1% 质量）。**[二手引用/论文实测于该后续工作]** → 对插件启示：难度应尽量做到**子任务/步骤级**而非仅任务级。
- 训练反馈需要 oracle 答案（用基准答案计算成功信号），在无标准答案的真实插件场景需以替代信号（自评、用户反馈、校验器）近似。**[分析推断]**
- 实验基准偏 QA/代码/数学；λ、层数等超参需按域调。**[论文实测范围内成立]**

## 2. 模型路由方法综述

### 2.1 RouteLLM（学术基线，开源）

- Ong et al., [arXiv:2406.18665](https://arxiv.org/abs/2406.18665)（LMSYS，2024-06，v4 2025-02）。用 **Chatbot Arena 人类偏好数据**训练多个路由器（BERT / causal LLM / matrix factorization / similarity-weighted ranking），在推理时动态在强模型与弱模型之间二选一。
- 结论：**[论文实测]** 成本降低最高 **2 倍以上**而不牺牲回答质量；路由器对未见的强/弱模型组合有显著迁移能力（换模型不重训仍可用）。
- 训练数据消融（v4 HTML，[链接](https://arxiv.org/html/2406.18665v4)）：仅 Arena 数据在 OOD 基准上表现差（BERT APGR 0.438）；用「金标签数据 + LLM-judge 数据」增强后 causal LLM 路由器 APGR 提升到 0.622（+25.3%）。**[论文实测]**
- 对插件的启示：**二元强弱路由 + 偏好数据可低成本起步**；judge/金标签增强比纯偏好数据更稳。

### 2.2 FrugalGPT / LLM Cascades（级联回退）

- Chen, Zaharia, Zou, Stanford, [arXiv:2305.05176](https://arxiv.org/abs/2305.05176)（2023）。三类省钱策略：prompt 适配、LLM 近似（蒸馏）、**LLM cascade**（从便宜到贵的 API 链式调用，带置信度打分器决定是否提前停止）。
- 结论：**[论文实测，2023 年价格背景下]** 级联可在保持/超过 GPT-4 精度的同时把成本降到最高 98% 的削减幅度；不同 API 价格差可达两个数量级。
- 对插件的启示：**级联 = 天然回退策略**；置信度打分器（scorer）+ 提前停止是编排者「先便宜后昂贵」决策的骨架。注意其 scorer 在新任务上有分布偏移问题，GraphRouter 对其 Reward 有 ≥10.8% 的改进（见 2.3）。

### 2.3 GraphRouter（图结构路由，ICLR 2025）

- Feng, Shen, You, [arXiv:2410.03834](https://arxiv.org/abs/2410.03834)（2024-10，v2 2025-03）；[GitHub ulab-uiuc/GraphRouter](https://github.com/ulab-uiuc/GraphRouter)。
- 方法：把「任务-查询-LLM」构为异构图，利用节点间交互与嵌入预测新查询在效果-成本权衡下应选的模型；对**新任务、新 LLM 泛化更好**。
- 结论：**[论文实测]** 三种效果-成本权重场景下相比现有路由器至少 **+12.3%** 性能；新任务 ≥+9.5%；相比 FrugalGPT Reward ≥+10.8%（OpenReview 版，[PDF](https://openreview.net/pdf?id=eU39PDsZtT)）。
- 工程注意：后续对比工作指出 GraphRouter/RouteLLM 这类训练型路由器需要 GPU，CPU-only 时延迟大幅劣化（CPU 上比累计分数式方法慢 5460×）。**[论文实测，EMNLP 2025 Findings，[PDF](https://aclanthology.org/2025.findings-emnlp.606.pdf)]** → 插件若跑在本地 NAS/CPU，路由器模型要选轻量。

### 2.4 Router-R1（路由即推理，多轮）

- Zhang, Feng, You, [arXiv:2506.09033](https://arxiv.org/abs/2506.09033)（NeurIPS 2025）。把路由器本身实例化为一个 LLM，用 RL 训练其交替执行「think → route → 聚合」多轮动作，奖励含格式、结果正确性与成本（成本奖励 ∝ −m(P_LLM)·T_out）。
- 结论：**[论文实测]** 单轮一对一映射的静态路由器搞不定需要互补能力/聚合的复杂任务；多轮路由+聚合在 QA 基准上提升效果-成本权衡。
- 对插件的启示：路由不必一次定死——**多轮路由、每轮聚合中间结果**对复杂任务更优；成本可显式进奖励函数。

### 2.5 MasRouter（多智能体系统级路由）

- Yue et al., [arXiv:2502.11133](https://arxiv.org/abs/2502.11133)（2025-02）；[HF 页](https://huggingface.co/papers/2502.11133)。
- 把「路由」上移到 MAS 设计层：三个模块——**协作确定器**（要不要协作、什么协作模式）、**角色分配器**（设几个角色、什么角色）、**agent-LLM 路由器**（每个角色用哪个模型）；执行后按性能/成本反馈联合更新三模块。
- 结论：**[论文实测]** 在单 agent 路由（如 RouteLLM）之上同时优化协作模式/角色/模型选择，成本低于 SOTA 编排方法。DAAO 报告在 MATH 上以 65% 训练成本、41% 推理成本超过它——两者是当前「编排层调度」的最强对照组合。**[论文实测，交叉自 DAAO]**

## 3. 「智能体数量/深度按难度伸缩」研究

### 3.1 More Agents Is All You Need（同质智能体采样-投票基线）

- Li et al., Tencent, [arXiv:2402.05120](https://arxiv.org/abs/2402.05120)（2024-02，v2 2024-10）。纯「采样 + 多数投票」（Agent Forest）即可让性能随智能体数量单调提升，且**提升幅度与任务难度正相关**；方法与复杂方法正交。
- 借鉴点：**[论文实测]** 难任务的增益主要来自并行采样而非角色分工——对难查询，最便宜的扩容手段是并行多采样+投票，而不是加复杂角色链。

### 3.2 MacNet：多智能体协作网络规模化

- Zhang et al., [arXiv:2406.07155](https://arxiv.org/html/2406.07155v3)（2024-06）。把智能体组织为 DAG 协作网络（监督 critic 边 + 执行 actor 节点），可扩展到 >1000 个智能体；观察：任务**可分解性**高的任务受益于规模化，低可分解任务收益递减。**[论文实测]**
- 借鉴点：团队规模的上限应与任务可分解性挂钩；DAG + 角色分工是大规模下可维护的拓扑。

### 3.3 Towards a Science of Scaling Agent Systems（Google DeepMind 等，最系统的实证）

- Kim et al., [arXiv:2512.08296](https://arxiv.org/abs/2512.08296)（2025-12，v3 2026-04）。260 种配置 × 6 个 agentic 基准 × 5 种架构（Single / Independent / Centralized / Decentralized / Hybrid）× 3 个 LLM 家族，受控评测后拟合预测模型（交叉验证 R²=0.373；用任务能力度量时 R²=0.413）。
- 关键发现 **[论文实测]**：
  1. **能力饱和**：单智能体基线超过一定性能后，协调的边际收益递减——强模型时代「多智能体税」更重；
  2. **工具密集型任务**承担多智能体协调开销，常不划算；
  3. **无中心化校验的架构错误传播更多**；
  4. 相对单智能体基线的增益区间为 **+80.8%（可分解金融推理）到 −70.0%（序列规划）**——架构-任务错配会大幅劣化；
  5. 该框架为 87% 的 held-out 配置正确选出最优架构。
- 借鉴点：编排者需要的不是「几个专家」一个数，而是**（架构 × 专家数 × 模型能力）的联合选择**；对不可分解/序列任务应降级为单专家+强模型。

### 3.4 通过多样性理解智能体规模化（信息论边界）

- Yang et al., [arXiv:2602.03794](https://ar5iv.labs.arxiv.org/html/2602.03794)（ICML 2026 接收）。信息论框架：MAS 性能受任务内在不确定性 H(Y|X) 上界约束，**同质智能体（同模型/同提示/同工具）收益迅速递减**；提升取决于「有效通道」数——独立、非冗余的推理路径数。**[论文实测（理论+实验）]**
- 借鉴点：编排者给难题加专家时必须保证**专家异构性**（不同模型/提示/工具面），数量应 ≈ 有效互补视角数，而非任意扩容。

### 3.5 难度感知的测试时预算分配（同类机制在单模型内的映射）

- **Plan and Budget**：[arXiv:2505.16122](https://arxiv.org/html/2505.16122v1)——轻量规划函数把问题分解为子问题并估计每个子问题的复杂度分数 π_i，再按预算分配测试时算力。**[论文实测]**
- **AdaCtrl**：[arXiv:2505.18822](https://arxiv.org/abs/2505.18822)——按难度对推理预算做自适应控制（难则放宽预算，易则收紧）。**[论文主张/实测]**
- **工作流优化综述**（From Static Templates to Dynamic Runtime Graphs，[arXiv:2603.22386](https://arxiv.org/html/2603.22386)）：把动态性排成谱系（子图选择 → 预执行生成 → 执行中改写），核心设计问题是「任务真正需要的最小可塑性」，灵活性上移会增加验证、停止与预算控制负担。**[综述]**
- 借鉴点：难度→预算的映射机制与多智能体编排同构，可直接移植为「每个专家/步骤的 token 与模型档位预算」。

### 3.6 MaAS（查询级 agentic supernet，DAAO 的直接对照）

- Zhang et al., 2025（DAAO 引文，代码与论文见 DAAO 相关工作节）；为每个查询从 supernet 采样一个定制的多智能体系统。DAAO 将其扩展为「难度感知 + 异构模型路由」。**[论文实测（见 DAAO 对照表）]**

## 4. 面向「编排者插件」的可落地设计启示（8 条）

1. **难度分级信号要可学习、可在线校准**：起步用 RouteLLM 式轻量分类器（Arena/judge 数据训练，[arXiv:2406.18665](https://arxiv.org/abs/2406.18665)）；上线后像 DAAO 一样用**工作流成功/失败作为 reward-like 信号**在线微调难度估计（成功→降难度，失败→升难度），不依赖人工难度标签（[arXiv:2509.11079](https://arxiv.org/abs/2509.11079)）。证据强度：论文实测。
2. **难度做到子任务级，而非整任务标量**：DAAO 的整轨迹单一难度分被后续工作证明会按最难步骤为所有步骤供给资源（成本削减仅 36.2%）；插件应先分诊任务、再对每个子任务估难度并分别定模型档位与预算。证据强度：论文实测（[arXiv:2609.22951](https://export.arxiv.org/pdf/2609.22951)）。
3. **路由目标函数显式含成本项 + 三档偏好**：DAAO 用成本惩罚系数 λ、Router-R1 把成本写进奖励、Not Diamond 提供 quality/cost/latency 三种偏好开关。编排者应暴露「效果优先/均衡/成本优先」旋钮，并把单位成本元数据（模型价目、专家 token 记账）作为路由输入。证据强度：论文实测 + 产品宣称。
4. **简单任务走单算子快路径，复杂任务才升级多专家**：DAAO 对简单查询只生成单算子工作流；DeepMind 实验表明单智能体基线足够强时协调收益递减、序列规划类任务多智能体反降 70%。判据可取：任务可分解性 + 工具密集度 + 单专家置信度。证据强度：论文实测。
5. **内建级联回退链**：借鉴 FrugalGPT cascade 与 OpenRouter 会话粘性——便宜模型/单专家先行，置信度不足再升级强模型/多专家；多轮任务记住上轮落定的模型/专家组合，只在它不再是 top 候选时才切换，保证会话连贯。证据强度：论文实测 + 产品宣称。
6. **扩专家数 = 加独立视角，且需中心化校验**：More Agents 证明难任务可靠并行采样+投票扩容；2602.03794 证明同质专家收益受限（有效通道数封顶）；DeepMind 证明无中心校验的架构错误传播更多。给难题加专家时保证专家异构（不同模型/提示/工具），并固定一个 Review/校验算子。证据强度：论文实测。
7. **路由不必一次定死，支持多轮路由与聚合**：Router-R1 表明 think→route→聚合的多轮路由优于单轮一对一映射；编排者可在每步后重估剩余难度并改派后续专家/模型。证据强度：论文实测。
8. **控制路由器自身的延迟与算力**：训练型路由器（GraphRouter/RouteLLM）CPU-only 时延迟劣化可达数千倍；本地 NAS 场景应选轻量分类器/规则+嵌入混合方案，并参考 RouterBench 类 cost-quality 前沿评测定期校准。证据强度：论文实测 + 第三方基准。
