## 1. 信息架构（沿用 v1 主体，修订 3 点）

四泳道纵向分组、异常非空置顶、阻塞是卡片徽章不是泳道、组内 `updated` 降序——**全部沿用 v1 §1**。修订仅以下三条：

### R1 · done 泳道自动折叠初值（修缺陷②的根）

- 初载折叠条件由「done ≥ 3」改为：**done ≥ 3 且存在非 done 任务**。
- 全板完成（done = total > 0）时**永不自动折叠**——此时 done 是唯一内容，折叠等于空白板。
- 会话中途最后一张卡完成（done 恰好达到阈值）**不触发自动折叠**（现状已如此，明文化）：折叠只发生在初载，运行中绝不偷偷收起用户正盯着的区域。
- 用户手动折叠后按 board 维度在会话内记忆（见 §8 保留域）。

### R2 · 空泳道呈现（与 T1 §4.2 的边界裁决）

| 场景 | 窄档 <720 | 宽档 ≥720 |
|---|---|---|
| 需要注意 空 | 整组隐藏（沿用现状，3112 行） | 泳道头 + 弱占位 |
| 进行中/待处理 空 | 只渲染泳道头 + 计数 0，**不渲染占位条**（窄档每一行高度都贵） | 泳道头 + 弱占位条 |
| 已完成 空 | 只渲染泳道头 + 计数 0 | 泳道头 + 弱占位条 |
| 全板完成 | 完成横幅（§4.2）+ done 卡全列 + 三个 0 泳道头（无占位条） | 横幅 + 2 列 done 网格 + 0 泳道头（占位条可留） |

- 0 泳道头**保留不隐藏**：「没有进行中/待处理」本身就是信息（全完成态的故事由这些 0 讲完）；窄档只是不给它们配占位条。
- 与 T1 的冲突条款：T1 §4.2「横幅下方泳道照常渲染（空泳道头 + 虚线占位）」按本表执行——窄档无占位条，宽档保留；T1 已声明冲突时以 T2 为准并回写。

### R3 · 全板完成态横幅（机制归本文，视觉归 T1 §4.2）

- 触发：board 渲染就绪且 `done === total > 0`。
- 行为：**纯状态展示，零交互**——不可点、不可关、无按钮；位于摘要条之下、泳道区顶部，随板区滚动。
- 文案（key 见 §9）：主文「全部完成」+ 计数「{done}/{total} 已完成」；无「用时」字段承诺（数据面无此字段，T1 §4.2 的「用时 34 分钟」仅为视觉示意，实现以现有 `loadedAt` 相对时间为准）。
- 通告：横幅出现时经 aria-live polite 播报一次（§7-A3），重复刷新不重复播报（对比 revision 变化）。

## 2. 工具条与摘要条契约（缺陷①的交互面）

P0-1 修好后仍需以下契约防回归（任何视觉方向都必须满足）：

1. **单行契约**：工具条恒为一行，高 40px，sticky 于板区顶部；内容顺序：标题（可截断 ellipsis）→ `r{revision}` → watch 点 → 弹性 spacer → 自动刷新开关 → 刷新 → 筛选（任务 ≥8 才出现）。任何座位宽度下**标题与按钮不得重叠、不得换行**。
2. **极窄裁剪顺序**（容器 <360px 时依次裁剪，只裁这两项）：先隐藏 `r{revision}` 文本，再隐藏 watch 点；开关/刷新/筛选三按钮永不裁剪（它们是唯一动作面）。
3. **摘要条折行规则**（沿用 v1 §4）：进度条 + 计数一行；`{n} 分钟前更新` 与 watch-off 图标在窄档折到第二行右对齐；永不横向滚动。
4. 计数为 0 的摘要徽章不显示（沿用现状）；全完成时摘要条 = 满格进度条 + done 计数 + 横幅在下方接力（§R3）。

**验收语句**

- A1：真机 50% 分屏（座位约 700px）打开任务板：工具条为一行，「任务板 r29」完整可读，右侧开关/刷新按钮与标题之间有可见间隙，无重叠、无换行。
- A2：真机 20% 分屏（座位约 300px）：工具条仍一行；`r29` 文本消失（<360 裁剪生效），标题截断为「任务板…」，三个图标按钮完整可点。
- A3：真机手机全屏（<768px 自动全屏）：摘要条最多两行——第一行进度条+计数，第二行「{n} 分钟前更新」右对齐；无横向滚动条。

## 3. 卡片与展开（取舍重审，沿用为主）

以下**沿用 v1 §1.3 / §2c 并与实现核对一致**，此处只列与实现有出入或需明文化的点：

1. **收起态字段优先级**（供 §5 密度阶梯裁剪时排序）：阻塞徽章 > ID > 标题 > owner > scope chips。任何降级都从优先级尾部开始裁，阻塞徽章在任何档位都不可裁。
2. **手风琴单开**：`expandedId` 单值；点击另一卡自动收起前一张；点击已展开卡头或 Esc 收起；展开区顶部内容顺序 = fail 错误块 → desc → dep 清单 → 复制按钮 → summary（实现顺序，fail 置顶原则与 v1 一致）。
3. **复制任务 ID**：成功后按钮文字就地变「已复制」2s（实现 2923–2934），同时 aria-live 播报（§7）。剪贴板 API 不可用时静默降级为播报 id 本身（听屏用户可复读）——不弹 toast（实现现状，接受）。
4. **dep 行**：纯文本（裁剪裁决见 §0.2）；未满足依赖行有阻塞标记与「等待 {taskId}（{owner} · {status}）」一句话，failed/escalated 卡的 fail 块仍在展开区最上。
5. **deep link `#task=T3`**：仅挂载时生效——滚动至卡（block:center）+ 2s 高亮 + 卡展开；重复导航同一片段不重复触发。会话消息里的板文件链接由宿主 patterns（`dsh-resource://file/**.expert-taskboards/**`）打开 tab，行为已满足 v1 §2d 的 1/2/4 步，3 步由上句覆盖。

**验收语句**

- A4：真机点击任一收起卡：该卡展开显示 fail/desc/dep/复制按钮/summary（有则显），同时前一张展开卡自动收起；再点该卡头或按 Esc：收起，焦点仍在卡头上。
- A5：真机点击展开卡内「复制任务 ID」：按钮文字变「已复制」约 2 秒后复原；粘贴可得到任务 ID。
- A6：真机会话聊天区点击 `.expert-taskboards/*.json` 链接：任务板 tab 打开；点击聊天里 agent 输出的 `#task=T3` 深链后重开 tab：T3 卡展开、视口居中、有约 2 秒高亮（`prefers-reduced-motion` 开启时为静态高亮）。

## 4. 空态全目录（缺陷②核心交付，v1 §6 扩为 9 态）

> 公共排版沿用 v1 §6：图标 + 标题 + ≤2 行正文 + ≤2 按钮，垂直居中；「空而不茫」——每个态都要回答用户三个问题：**现在是什么状况 / 为什么 / 我能做什么**。

| # | 态 | 触发 | 行为与文案（key 见 §9） | 动作 |
|---|---|---|---|---|
| E1 | 无板 | 顶层 0 个 `*.json` | 「还没有任务板」+ 指引正文（沿用） | 「查看使用说明」（就地展开帮助文本）+「重新检测」 |
| E2 | 多板歧义 | 顶层 ≥2 个 `*.json` | 「检测到多个任务板」+ 候选只读清单（深链来源标「来自聊天链接」）| 「重新检测」；**不提供**强制渲染入口（宁漏勿错，沿用） |
| E3 | broken | JSON 解析失败 | 「任务板格式无法解析」+ 原因 | 「重新检测」 |
| E4 | 空板 | 1 个 json，tasks 空 | 「任务板已就绪，还没有任务」 | 「重新检测」 |
| E5 | **全板完成** | done = total > 0 | §R3 横幅「全部完成 · {done}/{total} 已完成」+ done 泳道**不折叠**全列 + 三个 0 泳道头（R2） | 无（纯状态）；done 计数 ≥3 时泳道头仍有手动折叠按钮 |
| E6 | **done 折叠态** | 用户手动折叠 done（≥3）| 泳道头常显「已完成 (9)」+ 折叠箭头翻转；折叠区不渲染卡片 | 点泳道头箭头展开；折叠时若焦点在 done 卡头 → 焦点迁到该折叠按钮（§7-F2） |
| E7 | 过滤空 | 过滤生效且 0 匹配 | 窄档：整板空态「无匹配任务」+「清除过滤」；宽档：各泳道保留、计数显示 `0/m`，不出整板空态（沿用现状 3318–3323） | 「清除过滤」一键还原 |
| E8 | 加载失败 | 初载 list/read 异常 | 「任务板加载失败」+ 错误摘要（截断，title 全文） | 「重试」 |
| E9 | 刷新失败（有旧数据） | watch/手动刷新异常但已有渲染 | 板区顶部内联条「刷新失败，显示上次数据」+ 失败时刻 + 「重试」（沿用现状 3250–3256）；**不推翻现渲染** | 「重试」 |

微态（不成空态，只做指示）：watch 关闭 → 摘要条尾部灰色 off 图标 + title「自动刷新已关闭」（沿用）；刷新成功无变化 → 无任何提示（静默即反馈）。

**验收语句**

- A7（E5）：真机准备一块 9/9 全 done 的板：板区顶部出现完成横幅「全部完成 · 9/9 已完成」，其下 9 张 done 卡**全部可见**（未被自动折叠），进行中/待处理/需要注意泳道头计数为 0；板面不再是几行裸泳道头。
- A8（E5 通告）：开启读屏后在板从 8/9 → 9/9 的刷新后：读屏播报一次「全部任务已完成」类文案；随后无变化的刷新不重复播报。
- A9（E6）：真机点击「已完成 (9)」泳道头的折叠箭头：9 张卡收起，箭头翻转；再点展开还原；折叠期间泳道头计数 (9) 恒可见。
- A10（E7）：真机 20% 分屏，筛选「仅看阻塞」且无阻塞卡：板区显示「无匹配任务」+「清除过滤」；点击后恢复全部卡片。
- A11（E9）：真机断开后端（或令请求失败）时点刷新：板面卡片原样保留，顶部出现「刷新失败，显示上次数据」内联条；恢复后点「重试」：内联条消失，数据更新。

## 5. 窄栏密度阶梯（缺陷③交互面，与 T1 §4.3 衔接）

断点全部按**容器宽**（ResizeObserver，v1 裁决不变）。四档：

| 容器宽 | 档位 | 收起卡布局契约 |
|---|---|---|
| <300px | 兜底档 | 按 T1 §4.3：标题单行截断、隐藏 scope chips 仅留阻塞徽标（防御性，正常座位不触发） |
| 300–479px | **紧凑档（本节新增）** | 收起卡 ≤2 行：行 1 = 状态点 + ID + 标题（单行截断）+ 阻塞徽章；行 2 = owner + scope **计数**（如「3 个文件」，替代逐条 chips） |
| 480–719px | 标准档 | 沿用现状：标题 2 行截断 + meta 行 + badges 行（≤2 chips + `+n`） |
| ≥720px | 宽档 | 标准档字段 + done 泳道内部 2 列 grid（v1 §4 沿用）；泳道四列网格，上限 1440px 居中 |

- 字段裁剪永远从 §3-1 优先级尾部裁起；**阻塞徽章与 ID 任何档位不裁**（聊天引用锚点 + 唯一异常信号）。
- 泳道组头恒 28px 单行（点 + 名 + 计数 + 折叠钮），任何档不折行。
- 触控目标：全屏档（<768px 自动全屏）卡片整行可点已 ≥44px，沿用；分屏浮层档鼠标精触达不强制。
- 宽档四泳道网格含 0 泳道（R2）；窄档纵向堆叠。

**验收语句**

- A12：真机 20% 分屏（座位约 300px）：每张收起卡高度不超过两行文本；scope 不逐条显示而是一个计数；阻塞卡上「阻塞 {n}」徽章仍可见；无横向滚动条。
- A13：真机 40% 分屏（座位约 500px）：收起卡为标准三行形态（标题可两行、meta 行、badges 行）；展开任一卡后其余卡不跳动。

## 6. 过滤（实现形态为 v2 基线，修两点）

**接受的实现形态**（取代 v1 §5 常驻 chips 行）：

- 筛选入口 = 工具条筛选 icon 按钮，**任务 ≥8** 才出现；过滤行仅在按钮展开时渲染（窄档不留常驻行）。
- 过滤维度三选可组合：状态多选 chips（含计数）、「仅看阻塞」开关 chip、owner 单选 chips（distinct owner ≥3 才出现）。
- 「重置」仅在过滤生效时出现；过滤条件会话内保留、不持久化（§8 L1/L3 除外）。
- 明确不做（沿用 v1）：文本搜索、按泳道过滤（泳道即分组）、多选 owner、持久化。

**修订两点**：

- R1 · 过滤生效时泳道头计数显示 **`n/m`**（如 `1/3`；未过滤保持纯计数）——恢复 v1 承诺，扫视「过滤吃掉了多少」零成本。
- R2 · 过滤结果变化经 aria-live 播报一次：「筛选后 {n} 项」（§7-A4）。

**验收语句**

- A16：真机任务 ≥8 时工具条出现筛选按钮；点击展开过滤行（状态 chips + 仅看阻塞 + owner chips）；点状态「进行中」后：只剩进行中卡，各泳道头计数变为 `n/m` 形式；再点该 chip 取消。
- A17：真机同时开「仅看阻塞」+ 某 owner：结果为两条件交集；点「重置」一键全部还原，泳道头恢复纯计数。

## 7. 键盘与读屏（v1 §7 沿用 + 焦点防护 + aria-live 清单）

**沿用**（与实现核对一致）：卡头 `button[aria-expanded]` + 展开区 `role=region`/`aria-labelledby`；Enter/Space 展开；Esc 收起（展开区内 Esc 焦点回卡头）；↑/↓ 全局 roving 循环、Home/End 跳首/末卡；卡头可访问名 = `ID · 标题 · 负责人 X · 状态 · n 项阻塞`；焦点环 2px；`prefers-reduced-motion` 全量降级。

**新增焦点防护**（防「焦点卡消失」）：

- F1 · 过滤导致焦点卡被隐藏 → 焦点移到过滤行「重置」按钮（E7 态）或工具条筛选按钮。
- F2 · 折叠 done 泳道导致焦点卡被隐藏 → 焦点移到该泳道折叠按钮。
- F3 · 数据刷新泳道迁移导致焦点卡移位 → 焦点跟随卡 id（keyed 不变即不丢；卡被删除 → 焦点回该泳道组头）。

**aria-live 清单**（单一 polite 区，沿用现状实现，扩展触发源；同一刷新批次合并为一条播报）：

| 触发 | 播报文案（key §9） |
|---|---|
| watch/手动刷新有变化 | 已更新 · {n} 项变化（沿用） |
| 复制任务 ID | 已复制（沿用） |
| done 泳道折叠/展开 | 已完成泳道已折叠 / 已展开 |
| 过滤结果变化 | 筛选后 {n} 项 |
| 全板完成横幅出现 | 全部任务已完成 |
| 刷新失败（E9） | 刷新失败，显示上次数据 |

**验收语句**

- A18：真机键盘走查：Tab 依次到达 开关→刷新→筛选→（过滤行）→各卡头→展开区内复制按钮；无键盘陷阱；焦点环全程可见。
- A19：真机聚焦某卡头按 ↓：焦点到视觉顺序下一张卡头（跨泳道连续）；Home/End 跳首/末卡。
- A20（F2）：真机焦点在 done 泳道某卡头时按折叠钮：卡收起，焦点落在折叠按钮上而非 body。
- A21（F1）：真机筛选使焦点卡隐藏：焦点落在「重置」（或筛选按钮），按 Enter 可一键还原。
- A22：开启读屏，过滤后：播报「筛选后 n 项」；done 折叠时：播报「已完成泳道已折叠」。

## 8. 座位三模式与状态保留域（硬约束的交互落点）

宿主座位三模式：20%–80% 分屏、<768px 自动全屏、浮层；**split/全屏/浮层切换按会话保留状态**。断点一律按容器宽测量（模式只影响容器宽度，不引入独立断点分支）。

**UI 态保留域分三级**（此前 v1 未区分，这是「刷新不移动视线」纪律的完整边界）：

| 级 | 场景 | 必须保留 |
|---|---|---|
| L1 | watch/手动刷新、tab 可见性切换（隐藏→恢复）、E9 失败重试 | 全部：expandedId、泳道折叠态、过滤条件、滚动锚点、焦点卡 |
| L2 | 分屏 ↔ 全屏 ↔ 浮层切换 | 同 L1（宿主不卸载 tab；若容器宽跨档，仅布局按 §5 换档，UI 态不变） |
| L3 | tab 关闭后重开（实现 keepMounted:false 会卸载，lib/client.js:2157） | **新增需求**：模块级会话内缓存（按 sessionId+board 键存 expandedId/泳道折叠/过滤/滚动锚点），重开时恢复；零依赖、不写盘。深链 `#task=` 重开仍优先生效（展开+高亮）后缓存让位 |

- 滚动锚点机制沿用实现（视口顶部首个卡头 offset 差值回滚，2767–2773、2886–2894）。
- watch 关闭期间不轮询不播报；恢复可见立即比对一次（沿用）。

**验收语句**

- A23：真机 40% 分屏展开 T3、过滤 owner X 后，把座位拉到 80% 再拉回：T3 仍展开、过滤仍在、滚动位置与焦点卡不变，仅卡片布局按新宽度换档。
- A24：真机 <768px 设备切自动全屏再切回浮层：同 A23 的保留项全部不丢。
- A25：真机关闭任务板 tab 再从页头徽标重开：上次的展开卡/折叠态/过滤恢复（L3）；若带深链则深链优先。
