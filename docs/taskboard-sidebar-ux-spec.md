# 专家模式任务板 Sidebar — 信息架构与交互规格

> 版本 v1.0 · 设计文档（不含代码） · 载体：DSH Web GUI 右侧 Sidebar 自定义 tab
> 定位：只读进度看板。主场景「瞄一眼当前进度 + 点开看某个任务详情」，信息不喧宾夺主。

---

## 0. 设计原则（决策依据）

1. **扫视优先**：任何状态一眼可得（摘要条 + 泳道计数），细节二级获取（卡片展开）。
2. **宁漏勿错**：定位规则沿用顶层恰一个 `*.json` 才渲染；歧义态一律给指引不猜数据。
3. **纯只读**：UI 无任何写路径；所有动作是「看、过滤、跳转、复制 id」。
4. **规模自觉**：3~15 任务，不上虚拟列表、不上全文搜索、不上多级过滤。
5. **刷新不打扰**：数据更新永不移动用户视线焦点（滚动位置、展开态、焦点全部保留）。

## 1. 信息层级

### 1.1 泳道分组：取舍与结论

**候选方案**
- A. 固定四泳道（映射 8 状态）
- B. 状态精简映射（三泳道：待办/进行中/完成，异常只作卡片徽章混排）

**评价**
- Sidebar 是**纵向堆叠的分组列表，不是横向 Kanban**。窄面板 300~500px 排 8 列不可能，排 4 列也不行——泳道在这里天然是纵向 section，横向列式方案直接排除。
- 方案 B 的问题：failed/rejected/escalated 混在待办里时，"哪里出了问题"需要逐卡扫视，违背扫视优先；且阻塞徽章也是卡片级，两种异常信号（状态异常 / 依赖阻塞）会挤在同一层。
- 方案 A 的问题：8 状态直接 8 组过碎（draft/pending/ready 用户不关心区分度）。

**结论：采用方案 A 的四泳道映射，但做两处修正**

| 泳道 | 映射状态 | 排序 | 默认折叠 |
|---|---|---|---|
| 需要注意 Needs Attention | failed, rejected, escalated | **非空时置顶**，空则整组隐藏 | 永不折叠 |
| 进行中 In Progress | running | 2 | 展开 |
| 待处理 To Do | draft, pending, ready（dep 未满足的卡带阻塞徽章） | 3 | 展开 |
| 已完成 Done | done | 4 | done ≥ 3 张时默认折叠，组头常显计数 |

- **异常泳道置顶**：出问题的事最先被看到；为空时整组不渲染（避免四个空标题稀释信息密度）。
- **draft 降权**：draft 是 PM 草稿，卡片用次级样式（文字色降一档），不参与进行中计数。
- **阻塞不是泳道**：dep 未满足是卡片级徽章（⛔ Blocked），出现在任何泳道；摘要条单独计数 `1 blocked`。理由：阻塞是依赖关系属性，与状态正交，硬拆泳道会导致同一任务在"状态"与"阻塞"两个维度被拆到不同组。
- 组内排序固定：`updated` 降序（最近活动的靠上），稳定可预期。
- 组头格式：`▍进行中 (2)` + 折叠箭头；异常组头加红色计数点。

### 1.2 板头摘要条（为"瞄一眼"而生）

泳道之上固定一条单行摘要（progress glance 的第一落点）：

```
[■■■□□□□□] 3/8 完成 · 2 进行中 · 1 阻塞 · 1 异常        rev 12 · 2 分钟前更新
```

- 迷你进度条（done/total）+ 2~4 个计数徽章；计数为 0 的徽章不显示。
- 右侧数据新鲜度：`rev N · 相对时间`。watch 开关关闭时此处换成灰色图标 + tooltip「自动刷新已关闭」。

### 1.3 卡片字段：最小集与渐进披露

**默认（收起）字段——一行卡片**

| 字段 | 呈现 | 说明 |
|---|---|---|
| 状态点 | 8px 色点 + 状态色 | 不只靠颜色，展开态/悬停有文字徽章 |
| ID | `T3` | 等宽字体，永远可见（聊天引用锚点） |
| 标题 | 单行截断 ellipsis | 唯一的主文本 |
| Owner | 12px 文字或 16px 头像色块 | 窄面板用色块首字，宽面板用名字 |
| 异常角标 | ⛔ 阻塞 / ✕ 失败（红） | 仅异常卡显示，占用优先级最高 |

展开后（渐进披露，按信息价值排序）：

1. **状态徽章全文**（含 failed/rejected/escalated 区分——收起态只有色点）
2. **fail 错误信息**（红色块，仅 failed/escalated；有则置顶，这是"为何失败"的直接答案）
3. **dep 依赖清单**：每个依赖一行 `T2 · running ✓已满足 / ⛔未满足`，未满足项红色；附自动生成一句话「等待 T2（owner X · running）」
4. **desc**：完成标准全文（white-space: pre-wrap 保留编号列表）
5. **scope[]**：文件路径 chips（可点复制路径）
6. **summary**：完成后的结果摘要（done 卡的核心增量）
7. **元信息行**：`创建 x 前 · 更新 x 前` + 「复制任务 ID」按钮

**展开模式**：手风琴单开（accordion，同时最多展开一张）。理由：面板窄、用户旅程是"看某一个任务的详情"，单开保持上下文不散；双开/多开在 300px 下必然丢上下文。点击已展开卡头部或按 Esc 收起。

## 2. 关键用户旅程

### a) 页头徽标 → 看进度

1. 页头 icon button 常驻，`aria-label="任务板（2 进行中）"`，徽标数字 = running 计数（0 时隐藏数字，保留图标）。
2. 点击：
   - tab 未开 → 打开 tab，渲染板；
   - tab 已开未聚焦 → 聚焦该 tab；
   - tab 已聚焦 → 收起/再点展开（toggle），不做其他动作。
3. 落地视点 = 板头摘要条。**不自动展开任何卡片**——用户第一需求是概览，不是详情。
4. 徽标计数变化（running 增减）→ 徽标做一次 300ms 缩放脉冲；仅此而已，不弹通知。tab 可见时徽标与板内数据同源，不可见时仍由页头轮询/watch 驱动（供"任务完成了回来瞄一眼"的回访动机）。

### b) 找某个 owner 的任务

- 规模 ≤15，**扫视可及**：卡片默认字段已含 owner。首选路径 = 看一眼。
- 增强路径：**owner chips 过滤行**（见 §5）：板头下方一行横向 chips `全部 · 最小变更工程师 · 前端工程师…`，点击 chip 过滤为只看该 owner 的卡（跨泳道保留泳道结构，各组计数变 `1/3` 形式）。再点取消。
- 不提供 owner 详情页、不提供按 owner 分组切换——一种视图够了。

### c) 看某任务为何阻塞 / 失败

1. 阻塞/失败的卡在收起态就有角标（⛔/✕），异常泳道置顶——发现成本趋近于零。
2. 点击卡片 → 手风琴展开，视点顺序即答案顺序：**fail 错误块在最上**（失败卡）→ **dep 未满足清单 + 一句话原因**（阻塞卡）→ desc/scope/summary。
3. 依赖行内可点击 `T2` → 收起当前卡、展开并滚动到 T2 卡（面板内跨卡跳转，200ms 滚动动画）。依赖链 = 天然的"阻塞溯源"路径，让用户沿 dep 走到根因。
4. 「复制任务 ID」按钮：把 `T3` 放入剪贴板，toast「已复制」，方便回聊天区问 agent。这是只读 UI 里最实用的"动作"。

### d) 聊天里点任务板文件链接直达

- 链接协议：会话消息中的 `.expert-taskboards/<board>.json` 链接点击后 →
  1. 打开/聚焦任务板 tab；
  2. 若该 board 已渲染：滚动至对应泳道区（200ms）；
  3. **支持 `#task=T3` 片段**：滚动至 T3 卡、自动展开、2s 黄色高亮脉冲（`prefers-reduced-motion` 时只做静态高亮）；焦点移至该卡（无障碍要求，§7）。
  4. 无片段：滚动至板头摘要条即可。
- 目标 board 未渲染（如多板歧义态中该文件未被选中渲染）→ 展示 §6 的歧义态并**高亮该文件条目**，文案点明"你点击的正是未渲染的候选文件之一"。
- 板内任务深链由 agent 在聊天里输出（如 `#task=T3`），规格约定即可，UI 无需额外入口。

## 3. 刷新与新鲜感（watch 防抖 500ms）

### 3.1 渲染稳定性（不跳动）

- **keyed 复用**：卡片 DOM 按 `task.id` keyed diff，只更新变化字段；未变化卡片不动 → 高度不变。
- **UI 态与数据态分离**：`expandedTaskId`、各泳道折叠态、滚动位置、owner 过滤均为 UI 态，任何数据刷新都**原样保留**。展开中的卡即使数据变了也保持展开（内容就地更新）。
- **滚动锚点**：刷新后以视口顶部第一个可见卡 id 为锚点，重渲染后把锚点卡滚回原视口偏移（≤15 任务，成本可忽略）。
- **排序确定性**：组内 `updated` 降序是纯函数；状态变化导致的泳道迁移用 200ms FLIP 位移动画让眼球跟得上（reduced-motion 时直接跳变），**绝不因此强制滚动视口**。
- 展开中的卡数据更新 → 展开区内容就地替换，卡片高度变化是自然的（用户正盯着它看，可接受）；其余卡高度由 keydiff 保证不变。

### 3.2 变化提示（新鲜感）

- **变化检测**：对比 `revision`（或 `event_state_hash`），无变化不重渲染、不提示。
- tab 可见时：静默更新 + 顶部非阻断 toast `已更新 · 2 项变化`（3s 自动消失，`aria-live=polite`）；实际变化的卡片做 2s 高亮脉冲。
- tab 不可见时：暂停 watch；恢复可见时拉取一次——有变化则同上提示（用户"回来"的动作本身就是查看意图，直接更新不问）；无变化则什么都不发生。
- **不做**"有更新，点击刷新"的确认式 pill——数据是只读的，自动更新无破坏性，确认步骤是负资产。
- toast 与徽标共用来源，running 计数变化额外触发页头徽标脉冲（§2a）。
- 手动刷新入口：板头 refresh icon（watch 关闭时的兜底），刷新后 toast `已是最新`（无变化）/ `已更新`。

## 4. 窄面板 vs 全屏自适应

断点按**面板实际宽度**（container query 语义，非 viewport），mobile-first：

| 面板宽度 | 布局 | 卡片字段 | 泳道 |
|---|---|---|---|
| < 420px（<768px 全屏 / 极窄分屏） | 单列 | owner 缩为首字色块，摘要条计数最多显示 3 个（完成/进行/异常，其余并入 `+n`） | 全部纵向堆叠 |
| 420 ~ 719px（常见 300~500 窄面板归此档下段） | 单列 | owner 显示文字名 | 全部纵向堆叠 |
| ≥ 720px（全屏 / 宽分屏） | 单列为主 | 完整字段；元信息行同行放更多 | 「已完成」展开后内部改 2 列 grid（`repeat(auto-fill, minmax(280px, 1fr))`），缓解 done 多时的纵向长度 |

- **泳道折叠规则**（任何宽度生效）：进行中/待处理默认展开；已完成 ≥3 张默认折叠（组头常显 `(5)`）；需要注意泳道永不折叠、非空置顶。用户手动折叠/展开记忆在会话内按 board id 保留。
- **何时单列**：单列是默认与常态；唯一的"多列"是 ≥720px 时已完成泳道的 2 列 grid。进行中/待处理永远单列——它们是注意力区，纵向扫读效率最高。
- <768px 自动全屏：沿用 <420px 档；触控目标 ≥44px（卡片整行可点已满足）。
- 摘要条在窄宽度折行规则：进度条+计数一行，`rev · 时间` 移到第二行右对齐，不横向滚动。

## 5. 过滤 / 搜索：做不做、做多少

**结论：不做文本搜索框；只做条件出现的 owner chips 过滤。**

- 3~15 任务 + 四泳道分组 = 全量扫视 <3 秒，搜索框是认知负担与误用面（还要处理清空态、无结果态），负收益。
- owner chips 触发条件：distinct owner ≥ 3 **且** 任务总数 ≥ 6 时才渲染该行（低于此阈值隐藏——过滤行本身也占一行高度，"简约"要求它有存在必要性）。
- 最简形态：单选 chip（含"全部"），点击切换；过滤生效时各泳道组头显示 `n/m`；无结果泳道显示 `0 匹配` 灰字而非隐藏组头（保留空间感，取消过滤后布局不跳）。
- 明确不做：多选、按状态过滤（泳道即状态分组）、关键字搜索、持久化过滤条件（会话内保留即可）。

## 6. 空态 / 歧义态（宁漏勿错的 UI 面）

| 态 | 触发 | 文案（zh） | 动作 |
|---|---|---|---|
| 无板 | 顶层 0 个 `*.json` | 标题「还没有任务板」/ 正文「任务板由 AI 在工作区 `.expert-taskboards/` 下创建（顶层恰好一个 `*.json` 文件时才会展示）。试试在聊天里说：『创建一个任务板』。」 | 主按钮「查看使用说明」（打开 guide 引导页）；次按钮「重新检测」 |
| 多板歧义 | 顶层 ≥2 个 `*.json` | 标题「检测到多个任务板文件」/ 正文「为避免展示过期或错误的数据，检测到 2 个候选文件时不会自动渲染。请让 AI 归档多余的文件，只保留一个，然后点『重新检测』。」+ 候选文件只读列表（文件名 + 修改时间；用户点击的深链来源文件高亮标注「来自聊天链接」） | 「重新检测」；列表项「复制文件名」（供回聊天引用）。**不提供**"强制选一个渲染"的入口——渲染决策归 agent，UI 只报事实 |
| 空板 | 1 个 json，`tasks` 为空 | 「任务板已就绪，还没有任务。让 AI 的项目经理先做任务分解。」 | 「重新检测」 |
| guide 入口 | 常驻 | guide 引导页胶囊入口固定在板头右侧，图标 + 「指南」 | 打开引导页（会话内记忆是否已看过，看过后收缩为纯图标） |

- 空态/歧义态共用一套排版：图标 + 标题 + 两行以内正文 + ≤2 个按钮，垂直居中，不做插画堆砌。
- watch 检测到文件出现/消失时，空态与正常态之间自动切换（同样静默 + toast）。

## 7. 无障碍与键盘（最小集）

- **语义**：泳道 = `<section>` + 可见 `<h3>` 组头；卡片头 = `button[aria-expanded]`（disclosure pattern），展开区 `role=region` + `aria-labelledby` 指向卡头。
- **键盘**：
  - Tab 顺序 = 视觉顺序（泳道 → 卡 → 展开区内的可交互元素）。
  - Enter/Space 在卡头上：展开/收起。
  - Esc：收起当前展开卡，焦点回卡头。
  - ↑/↓ 在卡片间移动焦点（roving tabindex，组内循环）；Home/End 跳首/末卡。
  - 全部功能（含 owner chips、复制、刷新、guide）均可 Tab 达，无键盘陷阱。
- **读屏**：
  - 卡头可访问名 = `T3 · 标题 · owner X · running · 阻塞`（状态与阻塞进 accName，不依赖颜色）。
  - 刷新 toast、徽标计数变化经 `aria-live=polite` 播报；toast 不抢焦点。
  - 深链跳转后焦点移至目标卡（§2d）；手风琴展开后焦点保持在卡头。
- **视觉**：状态 8 值 = 色点 **+ 图标 + 展开态文字徽章** 三通道；文本对比度 ≥ WCAG 2.1 AA（含暗色主题两套 token 均需过检）；焦点环 2px 高对比可见。
- **动效**：`prefers-reduced-motion` 时关闭 FLIP/脉冲/滚动动画，改为直接跳变 + 静态高亮。

## 9. 视觉 token 备注（对接设计系统）

- 状态色（亮/暗两套均需 AA）：draft/pending/ready 中性灰阶区分（ready 稍亮）、running 品牌蓝、done 绿、failed 红、rejected 橙、escalated 紫；阻塞角标用 failed 红但图标不同（⛔ vs ✕）。
- 间距沿用 4px 网格 token；卡片纵向间距 `--space-2`（8px，紧凑扫读），泳道间 `--space-6`。
- 等宽字体仅用于任务 ID 与 scope 路径。
- 高亮脉冲色与主题联动：亮色 `--accent-color` 30% 底、暗色同 token 20%。

## 10. 决策速查（One-line decisions)

1. 四泳道纵向分组（非横向 Kanban），异常组非空置顶；8→4 精简映射，保留原状态徽章。
