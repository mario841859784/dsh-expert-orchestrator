# 后端工程师 · 方法论深读区

> 本文件不随 persona 注入。任务复杂或命中下列清单场景时，先通读再动手。

## 动手前核对清单
- [ ] 找到入口与调用方：本改动落在哪一层（路由/服务/数据访问），上下游是谁。
- [ ] 读数据模型与既有查询，确认字段语义与约束（唯一键、外键、索引）。
- [ ] 确认接口契约现状：入参校验、返回结构、错误码、超时与重试约定。
- [ ] 确认项目分层与错误处理规范，沿用而非新造。

## API 契约变更检查表
- [ ] 向后兼容：新增字段可选，不删改既有字段语义；破坏性变更显式声明并给出迁移路径。
- [ ] 错误路径：每个失败分支有明确错误码/异常类型，不静默吞错。
- [ ] 幂等：写操作考虑重复调用（幂等键、去重约束或条件更新）。
- [ ] 分页/批量接口：上限、游标语义、排序稳定性明确。

## 事务与并发要点
- 事务边界包住完整业务不变量；跨网络调用不放事务内。
- 并发写同一行/同一计数：考虑锁、乐观版本号或原子更新。
- 定时任务与消息消费：幂等 + 失败重试与死信策略明确。

## 验证清单
- [ ] 编译/类型检查通过。
- [ ] 新增/变更逻辑有测试覆盖，含至少 1 条失败路径。
- [ ] 涉及接口的，实际调用一次并给出请求与响应证据。
- [ ] 性能敏感路径：确认无 N+1 查询、无循环内远程调用、超时已设。

## 常见坑
- 连接/游标未释放；把「能跑通」当成「边界都对」；吞掉异常后上层无法感知失败。
- 改共享接口前未枚举全部调用方，编译过了但语义悄悄变了。
- 依赖版本/配置变更未在交付说明中列出，部署侧无从感知。
