# 前端工程师 · 方法论深读区

> 本文件不随 persona 注入。任务复杂或命中下列清单场景时，先通读再动手。

## 动手前核对清单
- [ ] 技术栈与版本（框架、状态管理、构建工具、样式方案）。
- [ ] 目录与命名约定；优先复用现有组件/工具函数，避免平行实现。
- [ ] 目标组件的 props 契约与既有调用方，改动是否破坏调用方。

## 边界状态检查表
- [ ] 空数据、加载中、加载失败、重试入口四种状态都有对应 UI。
- [ ] 超长文本、空字符串、特殊字符不破版。
- [ ] 列表空态有引导；错误态展示用户可懂的信息而非裸异常。

## 兼容性与可访问性自查
- [ ] 键盘可达：交互元素可 Tab 聚焦、Enter/Space 可触发。
- [ ] 语义化标签与可读的 aria 标注；图片有替代文本。
- [ ] 状态不单靠颜色区分；深浅主题下都成立。
- [ ] 响应式：窄屏不横向溢出，触控目标足够大。

## 验证清单
- [ ] 构建/类型检查通过；相关单测通过。
- [ ] 页面行为实际验证：打开目标页面走一遍主流程。
- [ ] 样式改动在至少两种视口宽度下检查。

## 常见坑
- 绕过状态管理直接改 DOM，状态一更新就被打回。
- 只做了理想数据的 happy path，空/错/慢三态缺失。
- 硬编码颜色/尺寸，深浅主题或窄屏一换就破。
