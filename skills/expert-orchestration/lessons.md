## 2026-09-11 dsh-onebot 豆腐块排查与脚本双实现（专家编排会话）
- 排查「渲染失败字符」类问题，OCR 会被语言模型把豆腐块上下文补成通顺词（RapidOCR 把含 📋 的标题识别成完整「本轮中间记录」置信度 1.00），OCR 不能作为无豆腐块的证据；把字形转 ASCII art 逐字符比对 + 统计墨水量（空心豆腐块 ~200-340 px，真字形 ≥500，彩色位图 emoji 用非白像素 >1000 判定）才是可靠证据。
- 同一函数在两个脚本各实现一份（link-host.sh / build.sh 的 resolve_dsh_root）必然漂移：修 A 时 B 的同款缺陷不在改动面里就会漏。委派审查任务时先 grep 全仓同名函数/常量，把「双实现清单」写进任务书。
- 用户报「图片里存在 X」与像素级证据矛盾时，不迎合断言、给出字形证据并请用户指认位置，第二张截图（Web 端渲染）即定位成功；QQ 截图与 Web 截图是同一渲染管线的两种消费者，交叉比对能区分「内容缺字」vs「端侧字形缺字」。
- 运行中的 Cordis 插件进程不热加载 lib/（HMR 只重应用配置），改 lib 后必须重启宿主进程生效；涉及生产通道（QQ）的重启会让当前会话通道短暂中断，重启动作应交用户择时，验收分「磁盘 lib 已生效」与「live 进程已生效」两步记录。
- commit 前必查分支拓扑（git log --decorate + merge-base）：detached HEAD 上的修复 commit 有 GC 风险，且本地分支可能落后于部署 tag；把分支快进到已验证链前先 diff tag..main 确认方向，防止 checkout 把部署基线回退。

## 2026-09-12 缓存率优化改造 v1.4.0
- 本次改造目标是提高智谱（GLM）隐式前缀缓存命中率；缓存率只能在线上观察：经 new-api 聚合 `usage.prompt_tokens_details.cached_tokens / prompt_tokens`，本地无法直接测得。

## 2026-10-12 git 实施任务书默认启用工作树插件（用户裁决 2026-10-12）
- 涉及 git 实施的任务书（分支操作、历史改写/rebase、合并收口、多方案对比等写型 git 工作）默认要求使用 git 工作树插件（create_worktree）：写型专家在独立 worktree 分支上改动，主检出不动；「合并回主干 + 清理（git worktree remove + 删分支）」必须写进任务书的交付/完成定义，由专家执行、编排者验收。
- 版本门槛（能力探测门控）：该插件仅 DSH ≥ 0.2.1-alpha.2 提供（官方插件「Git 工作树」，随附 profile 默认关闭，需 GUI 插件页启用）。派发前以本会话工具清单是否注册 create_worktree 为准——未注册（低版本/未启用）一律不得在任务书写工作树要求，回退主检出改动并收紧 §3 写互斥红线；判定只读、静默降级、不必询问用户。
- 使用前提与实测行为：create_worktree 无仓库路径参数，作用于调用会话当前工作目录且必须是 git 仓库（非 git 目录报 fatal: not a git repository）；调用成功后会话 cwd 自动切到新工作树（离开用 working_directory 切回，检出与分支保留）；readOnly 召唤的专家不能自建 worktree，需编排者预建并把检出路径写进任务书。
